# 方法论：探针说明

## 配置预检 (`LLMTRACE-CFG-001`)

**测试目的**：验证用户输入配置的有效性。

**请求方式**：本地检查，不发送网络请求。

**客观证据**：协议是否受支持、模型名称是否为空、环境变量是否存在、重复次数/超时/Token 上限是否合法。

**风险推断**：配置无效时终止审计，不判定风险等级。

**误报来源**：无。

**不能证明什么**：配置有效不代表接口可信。

## 连接与鉴权探针 (`LLMTRACE-CONN-001`)

**测试目的**：验证 Base URL 可访问且鉴权方式正确。

**请求方式**：发送一次最小补全请求（`messages=[{"role":"user","content":"hi"}]`），记录响应。

**证据类型**：connectivity

**客观证据**：HTTP 状态码、Content-Type、异常信息。

**风险推断**：鉴权失败或网络不可达时，后续探针结果不可靠。

**误报来源**：部分服务商对简单请求返回非标准状态码。

**不能证明什么**：连接成功不能证明鉴权方式完全正确。

## 模型列表探针 (`LLMTRACE-MODL-001`)

**测试目的**：检查模型列表接口是否存在、目标模型是否在列表中。

**请求方式**：调用 `/v1/models` 接口。

**客观证据**：接口是否存在、HTTP 状态、模型数量、目标模型是否在列表中。

**风险推断**：模型列表接口不存在只记为警告；目标模型不在列表但可以调用只记为不一致；不能单凭模型列表认定造假。

**误报来源**：某些服务商返回空列表或不完整列表，但实际调用正常。

**不能证明什么**：模型在列表中不代表服务商真实调用了该模型。

## 正常基线探针 (`LLMTRACE-BASE-001`)

**测试目的**：建立正常请求的基线数据。

**请求方式**：默认执行三次，每次使用不同随机 nonce，提示内容简单、低成本且可验证。

**客观证据**：成功/失败率、延迟、返回文本、返回模型、Token、请求 ID、响应 ID、完成原因、响应结构指纹。

**风险推断**：全部失败为高风险；同一会话返回多个不相关模型标识（模型标识漂移）直接为高风险；部分失败为中风险。

**误报来源**：网络波动、服务商临时限流。

**不能证明什么**：成功请求不能证明模型身份真实。

## 无效模型探针 (`LLMTRACE-INV-001`)

**测试目的**：检测服务商是否忽略 `model` 参数或执行未披露的默认模型回退。

**请求方式**：使用 `llmtrace-invalid-<uuid>` 作为模型名发起请求。

**客观证据**：返回明确的 400/404（正常拒绝）或成功生成内容（高风险证据）。

**风险推断**：无效模型成功生成内容为高风险；返回鉴权/限流/服务器错误为结论不充分。

**误报来源**：部分服务商返回 400 但错误信息不明确。

**不能证明什么**：无效模型被拒绝不代表实际模型真实。

## 流式一致性探针 (`LLMTRACE-STR-001`)

**测试目的**：检测流式与非流式接口的响应是否存在差异。

**请求方式**：分别发送流式和非流式请求，对比结果。

**证据类型**：非流式对照请求为 `streaming_comparison`，流式请求为 `streaming_baseline`。两者均不属于 `baseline`，不参与稳定性与基线元数据分析。

**客观证据**：SSE 事件是否可解析、最终文本是否完整、返回模型和 Token 字段是否一致。

**风险推断**：流式接口不可用只作为协议能力证据；不一致不能自动判定为模型造假。

**误报来源**：流式协议实现差异、文本末尾空格差异。

**不能证明什么**：流式与非流式一致不能证明模型身份不变。

## 元数据完整性探针 (`LLMTRACE-META-001`)

**测试目的**：检查响应中关键元数据字段的完整性。

**请求方式**：基于已有证据分析，不发送额外请求。

**证据分析范围**：按证据类型分别检查 —— baseline 证据检查 model、usage、response_id、finish_reason 等生成字段；模型列表不要求 input_tokens、output_tokens、finish_reason；无效模型被正常拒绝时不要求模型和 Token 字段；流式证据按流式协议允许的字段位置检查。

**客观证据**：`model`、请求 ID、响应 ID、`usage`、输入 Token、输出 Token、`finish_reason` 字段的存在性。

**风险推断**：字段缺失分别记录，单个字段缺失不直接定为高风险。

**误报来源**：部分合法 API 实现不返回某些字段。

**不能证明什么**：字段完整不代表信息真实。

## 会话稳定性探针 (`LLMTRACE-STAB-001`)

**测试目的**：检测同一会话中基线请求的一致性。

**请求方式**：基于已有证据分析，不发送额外请求。

**证据分析范围**：仅分析 `evidence_type == "baseline"` 的证据，不将模型列表、无效模型、流式兼容性等请求混入分析。

**客观证据**：返回模型是否一致、状态码是否一致、响应字段集合是否一致、Token 字段是否忽隐忽现、延迟是否出现异常分组。

**风险推断**：模型标识漂移（返回多个不相关模型标识）直接为高风险；多项不一致为中风险；首版只做可解释的规则统计。

**误报来源**：服务商正常轮换后端、网络抖动。

**不能证明什么**：稳定性不能证明模型身份不变。
