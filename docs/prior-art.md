# 先行项目参考

## LLMmap

**解决的问题**：通过模型指纹识别 LLM 版本，类似于浏览器指纹识别。

**LLMTrace 可复用方向**：v0.5 计划适配 LLMmap 的指纹库，增强模型身份验证能力。

**当前不直接采用的原因**：首版优先建立独立的协议证据采集和风险分析框架。

**后续可能的适配方式**：将 LLMmap 指纹作为外部指纹引擎接入，与内部结构指纹互补。

## llm-verify

**解决的问题**：验证 LLM API 端点是否符合预期行为。

**LLMTrace 可复用方向**：类型推断和协议验证思路可参考。

**当前不直接采用的原因**：侧重于 API 功能验证，不包含无效模型回退检测和会话稳定性分析。

**后续可能的适配方式**：借鉴其协议验证方法，扩展 LLMTrace 的协议兼容性检查。

## Model Equality Testing

**解决的问题**：通过统计方法判断两个模型是否在实质上相同。

**LLMTrace 可复用方向**：v0.6 计划适配其统计模式，用于对比中转站返回的模型与官方参考模型。

**当前不直接采用的原因**：需要大量样本和计算资源，不适用于首版快速审计。

**后续可能的适配方式**：作为可选的高级分析模式，在用户需要深度验证时启用。

## Promptfoo

**解决的问题**：LLM 评估和红队测试框架，支持提示词评估、对抗测试和模型比较。

**LLMTrace 可复用方向**：v0.7 计划通过 Promptfoo 扩展评测能力，引入标准化的提示词测试集。

**当前不直接采用的原因**：Promptfoo 面向提示词评估，不是中转站审计工具；需要额外适配才能采集原始协议证据。

**后续可能的适配方式**：作为外部评测引擎，通过其 API 运行标准化测试，将结果纳入 LLMTrace 报告。

## lm-evaluation-harness

**解决的问题**：标准化的 LLM 能力基准测试（如 MMLU、HellaSwag 等）。

**LLMTrace 可复用方向**：v0.7 计划接入 lm-eval 作为外部能力评测引擎。

**当前不直接采用的原因**：首版聚焦于协议证据和风险分析，不涉及能力评测。

**后续可能的适配方式**：作为外部引擎，在用户需要能力基准验证时提供补充证据。
